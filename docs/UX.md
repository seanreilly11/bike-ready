# UX Design Principles

Reference this file when designing any screen, flow, or interaction. These principles apply to every UI decision — from forms and onboarding to pricing and upgrade prompts.

---

## 1. Smart Defaults
- Pre-fill every field with the most common or sensible choice — never leave forms blank
- The user's job should be to scan and adjust, not to fill from scratch
- If you already know the most likely answer, use it as the default
- Defaults signal a recommendation — use them intentionally

## 2. Progress & Momentum
- Never start a user at 0% — find something they've already done and count it
- Account creation, email confirmation, or any prior step counts as progress
- Show users where they are and how close they are to the end
- A visible, reachable finish line increases completion rates significantly
- Break long flows into steps; always show which step they're on

## 3. Give Before You Ask
- Don't gate value behind sign-up walls — let users experience something real first
- Show partial but genuinely useful results before prompting for an account
- The sign-up or upgrade ask should come after the user has already received value
- Free access to core functionality lowers the psychological cost of committing

## 4. Build Investment Early
- Let users make meaningful choices (name, preferences, style, goals) before asking them to register
- Every customisation decision makes the product feel more like theirs
- The more a user has built or configured, the harder it is to walk away
- Onboarding should feel like creation, not form-filling
- By the time the account screen appears, leaving should feel like a loss

## 5. Loss Aversion Over Gain
- Framing something as a loss is more motivating than framing it as a gain
- Show users what they stand to lose from inaction, not just what they'd gain from acting
- Make the cost of doing nothing concrete and visible (e.g. files at risk, streak ending, progress expiring)
- Avoid easy escape hatches like "maybe later" — the dismiss action should have weight too
- Apply this to upgrade prompts, trial expirations, and any call-to-action that's being ignored

## 6. Contrast & Anchoring
- The brain evaluates prices and values relative to what it saw first — control that anchor
- Never show a cost in isolation; always show it next to a larger reference point
- Place upsells, add-ons, or secondary pricing immediately after the user sees the primary (larger) number
- Use anchoring in pricing pages: a higher tier makes the mid tier feel reasonable
- The first number a user sees becomes the ruler they measure everything else against

---

## General Rules
- Users are not making logical decisions — they're responding to framing, context, and defaults
- Reduce the number of decisions required at any one moment
- Every screen should have one clear primary action
- Button labels should describe the outcome, not the mechanic ("Continue building" not "Submit")
- Empty states are not failures — treat them as invitations to act, with clear direction on what to do next
- Error messages should say what went wrong and how to fix it, never just that something failed
